# Model card: scam-tfidf-lr-v1 (scam message checker)

Feature AI-2. Trained in Python (`ml/`), scored in pure Go. Reproduce with `uv run nemml scam`.

## Intended use
Tell a customer whether a message they received looks like a scam, with reasons. Their text is checked and discarded: never stored, never sent to an LLM. The answer combines hand-written Nigerian scam rules, link checks and this text model; the rules alone work with no model (non-AI fallback), and the same rules run on the phone with no network. It is advice, not a verdict: it can be wrong in both directions, and it says why.

## Data
- **UCI SMS Spam Collection** (Almeida, Gomez Hidalgo, Yamakami, 2011): 5171 unique real English text messages, 13% spam. CC BY 4.0. Included.
- **Generated Nigerian messages**: 896 (`ml/src/nemml/scam_data.py`): bank impersonation, BVN/NIN updates, wrong-transfer tricks, advance fees, family emergencies, prizes, investment schemes, in English and Pidgin, and the legitimate look-alikes (bank alerts, real OTP notices that say "do not share", delivery and airtime notices, everyday chat that says "urgent").
- Split by message template (60/20/20, seed 7): held-out Nigerian messages are worded in ways the model never saw. Rows: train 3669, validation 1196, test 1202.
- No personal data. Phone numbers and amounts in generated messages are made up.

## Model
`TfidfVectorizer` (character n-grams 2 to 4 inside words, sublinear tf, L2 norm, 6000 terms) feeding `LogisticRegression` (balanced class weights). Exported as JSON (`model.json`, SHA-256 `269081f5955759aa505d4d6477c9be082dddb37f8c85b49a30f3847a4d702129`); `golden.json` holds 60 cases Go must reproduce, probabilities and fired rules both.
The model alone calls a message **suspicious** at 0.27 and a **likely scam** at 0.48 (chosen on validation data with realistic spam rarity, for 90% and 97% precision).

## Results on held-out messages
### Nigerian messages (112 scam messages; PR-AUC of the model alone 0.8727)

| Step | Precision | Recall | F1 |
|---|---|---|---|
| Rules baseline (message rules) | 100.0% | 78.6% | 0.880 |
| Model alone | 87.9% | 91.1% | 0.895 |
| **System (rules or model, whichever is stronger)** | 88.9% | 100.0% | 0.941 |

### SMS Spam Collection (English, not Nigerian) (118 scam messages; PR-AUC of the model alone 0.9439)

| Step | Precision | Recall | F1 |
|---|---|---|---|
| Rules baseline (message rules) | 88.9% | 6.8% | 0.126 |
| Model alone | 88.3% | 95.8% | 0.919 |
| **System (rules or model, whichever is stronger)** | 87.6% | 95.8% | 0.915 |

Legitimate Nigerian messages wrongly flagged (held-out, 42 messages from only 3 templates): rules alone 0.0%, system 33.3%; 1 of the 3 held-out templates are mostly flagged. With so few templates this is an anecdote, not a rate: a real customer will see false alarms, which is why the verdict is advice with reasons and not a block. The false alarm the rules guard against is a bank's own "your OTP is 482913, do not share it" notice, which mentions the OTP without asking for it.

## Limitations
- **The Nigerian data is generated by me.** There are only a few dozen templates, so the held-out Nigerian set is small (read it as a smoke test, not a benchmark), and the model has seen the style of scam I know how to write. Real scammers adapt.
- The SMS Spam Collection is 2011-era English spam from the UK and Singapore: it teaches "free prize, call now" wording, not Nigerian fraud.
- Links are judged by Go code (look-alike domains, short links, bare IP addresses), not by this model. Account numbers are not scored by it at all.
- Short messages and messages in Yoruba, Igbo or Hausa are weakly covered; Pidgin only by a few templates.
- Character n-grams can be gamed with odd spelling, which is why the rules and link checks run beside it.
- No fairness testing was possible: the data has no demographic fields, and names in templates are placeholders.
